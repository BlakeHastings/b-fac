- The code, whole-line comments aside, is the same in every copy.

## Architecture

ADR 0067 is added. **The choice was a separate region, with its own stamp, for each helper group, rather than a wider reader region:**

1. The groups live in different sets of files. The path helpers are in two files with no reader at all, `gitArguments` is not in this repository's merge guard, and the merge rule is not in the guest gate. One region could only cover them by shipping unused code into the files that lack a group.
2. The reader stamp is the line hosts already compare, and a change to a helper should not move it.

The cost is that a host compares more than one line. `references/enforcement.md` and the shipped guards say so, and the "covers this region only" note in each shipped reader comment is updated.

No shared module and no build step, so ADR 0029 stands. The module is still assembled at test time from the files that ship.

## Not done

- `scripts/guard-merge.mjs`'s `ghArguments` is left outside the command-arguments region. It compares the raw token (`tokens[0] !== 'gh'`) where the shipped copies call `commandName`, so `/usr/bin/gh pr merge 42` is allowed by this repository's merge guard and refused by the shipped one. ADR 0031 records this as a difference in the rules. Bringing it in would change a verdict, so it is out of scope here and noted for the orchestrator.
- Other near-copies between `check-setup.mjs` and `check-outward-writes.mjs` (`show`, and the `rootArg`/`START`/`ROOT` preamble) differ slightly and were not in the issue's list, so they are not regions.
